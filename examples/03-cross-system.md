# 模擬案例三：會議轉跨系統待辦

## 輸入逐字稿

M1：「小林週五前整理三家競品價格。」
M2：「客服問題需要彙整，負責人下次確認。」

## VAC

目標：產生待辦草稿，經核准後寫入任務系統；輸入：M1、M2、會議日期、時區與使用者權限；限制：未指定負責人不補造，沒有會議日期不推定週五的日期；輸出：草稿及成功寫入後的回執；驗收：資料可追溯、核准有效、無重複任務。

## 預期草稿

| 待辦 | 負責人 | 期限 | 來源 |
|---|---|---|---|
| 整理三家競品價格 | 小林 | 週五；確切日期待會議日期確認 | M1 |
| 彙整客服問題 | 待確認 | 待確認 | M2 |

## 路徑與操作邊界

LLM 擷取→對照原文→補齊必要日期與核准→API/工具寫入→取得任務 ID→回讀核對。MCP 視整合需要使用。

同一來源與同一決議使用穩定的去重鍵。若 API 逾時，先查詢是否已成功建立，不能直接重複建立。若缺權限、日期或核准，停在草稿，不宣稱外部寫入完成。

## 驗收

確認兩筆草稿的來源與缺漏；真正執行時另核對任務 ID、權限、去重及寫入內容。此套件沒有呼叫任何任務系統，所以外部整合狀態為未驗證。
