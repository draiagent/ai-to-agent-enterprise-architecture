# 🧠 AI to Agent：讓企業每一個任務，先做得成，再做得省

企業導入 AI，最值得問的問題是：「這個任務，能不能可靠完成？完成一次，總共花了多少 Token、時間與人力？」

有時模型單次收費便宜，卻需要反覆補資料、重新生成、人工修改；另一個模型雖然單次較貴，卻能用更少步驟完成。真正影響企業效益的，是從提出需求到驗收交付的整段過程。

因此，我們提出 AI to Agent Enterprise Architecture v1.0：一套以任務為中心、由大模型主導、以驗收與總成本管理執行過程的方法論。

它可以想成一家公司的工作系統：有任務單、有負責思考的主管、有資料庫、有工具，也有預算與驗收標準。

## ① VAD／VAC：先讓人與 Agent 看懂同一件事

許多任務失敗，起點就是需求不清楚。「幫我分析競品」看似簡單，實際上少了分析對象、期間、資料來源、輸出形式與完成標準。Agent 只能猜，猜錯就得重做。

VAD 是視覺化任務設計，用圖像、流程與少量文字，讓人快速看懂目標。VAC 則把意圖整理成可執行、可驗證、可交接的任務規格，包含：目標、輸入、情境、限制、行動、輸出、驗收。

例如，把需求改成：「比較三個品牌近半年公開產品與價格，製作比較表，標示來源與日期，缺漏資料不得猜測。」這就是 Promptless 的實務方向：用可重用規格，減少每次從頭撰寫提示詞。

## ② LLM／Agent：由大模型理解與規劃

大模型負責理解需求、推理問題、提出計畫；Agent 則結合模型、工具與執行狀態，持續推進任務。就像主管先理解目標，再安排查資料、計算與製作報告。

明確規則可以交給程式；特定分類、選擇或評分，可以評估使用 Jev 等結構化判斷模型。但是否加入，必須看實際效益。增加一次模型呼叫，也會增加整合、等待與驗證成本。

因此，Jev 是可選能力，適合時才用；大模型仍是主要理解與推理核心。

## ③ Knowledge／Memory／Context：資料要分清楚

這三個概念，可以用辦公室來理解：

- Knowledge 是資料櫃：放 SOP、研究、產品資料與可查證文件。
- Memory 是工作紀錄：記下過去決策、偏好，以及成功與失敗經驗。
- Context 是這次桌上的工作資料：依目前任務，取出相關知識、記憶、限制與最新狀態。

資料櫃很大，不代表每次都要把所有文件攤上桌。好的情境管理，是讓 Agent 取得足以完成任務的資訊，同時保留來源、版本與權限。

一般文件查詢可採 RAG；涉及跨文件關係時，可評估 GraphRAG；需要持續搜尋與調整方向時，再考慮多步檢索。這些是依問題選擇的方法。

## ④ 成本感知編排：選擇合適的完成路徑

編排系統要決定：用哪個模型？查哪些資料？呼叫什麼工具？何時重試？何時停止？

可以直接完成的工作，就直接完成；需要證據，就先檢索；超出權限或預算，就停止或交由人處理。

任務總 Token 必須涵蓋所有模型呼叫與重試，不能只看最後一段回答用了多少。Token 換算費用時，也要考慮模型與計費類別的差異。相同 Token 數量，不一定代表相同金額。

進一步衡量企業效益，可使用任務總成本 TTC，納入模型、檢索、工具、運算、人工與時間成本。各項應避免重複計算；重試產生的花費，歸入對應項目即可。

先達到品質與成功率標準，再比較每件成功任務的總成本。

## ⑤ Skill／MCP／API／Tool：讓執行分工清楚

- Skill：怎麼做。可重用的方法、步驟與注意事項。
- MCP：怎麼連。連接外部工具與資源的協定之一。
- API：怎麼呼叫。系統提供的服務介面。
- Tool：實際做什麼。搜尋、計算、讀寫與操作功能。

以競品報告為例，研究 Skill 指導查找與比較方法，搜尋工具取得資料，必要時透過 MCP 或 API 連接服務，最後產出報告。工具選擇應服務交付目標，並保留必要的操作紀錄。

## ⑥ Evaluation／Governance：完成要有證據

Agent 說「完成了」，仍需要依 VAC 檢查成果。來源是否存在？資料是否符合期間？比較欄位是否完整？有沒有把推測寫成事實？

驗收未通過，可在預算內補查、修正或重新規劃；達到重試上限，就應停止並說明缺口。治理則從任務開始貫穿全程，包括權限、資料來源、操作稽核與必要的人工決策。

通過驗收的成果，還要判斷是否值得寫入長期知識。失敗紀錄可以保存，但應標明狀態，避免日後被誤當成正確答案。

## 💼 實際怎麼開始？從一個反覆發生的任務做起

例如「把每週會議轉成待辦事項」：先用 VAC 定義輸入是逐字稿，輸出包含決議、負責人、期限與待確認事項；未提到的負責人與日期不得自行補上。

接著由 Agent 整理，必要時查閱專案資料，再逐項對照原文驗收。若要寫入任務系統，必須確認操作權限。

最後記錄總 Token、工具費用、處理時間、人工修改量與驗收結果，和原本做法比較。這樣才能回答：我們省下多少工作？品質是否維持？成本是否真的下降？

這套 v1.0 方法論，接下來需要透過個人知識整理、企業知識問答與跨系統任務持續驗證。

它的核心可以濃縮成五句話：任務優先。大模型主導。情境按需取得。品質達標後優化成本。驗收後審核知識寫入。

現在，請挑出公司裡一件每週都要做的工作：你能清楚寫出它的完成標準嗎？那就是 AI to Agent 最好的起點。

**先做得成，再做得省。**
