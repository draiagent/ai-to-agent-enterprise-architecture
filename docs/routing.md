# 任務選路與停止條件

先判斷任務目標、資料敏感度、即時性、關聯需求、行動風險、預算及期限。以下路徑可以組合，不是固定升級階梯。

| 情況 | 可評估路徑 | 驗證要求 |
|---|---|---|
| 已有完整可信輸入 | LLM 直接處理 | 核對輸入與輸出 |
| 精確規則或計算 | 程式規則／計算工具 | 測邊界值及規則版本 |
| 重複結構化分類 | 規則、LLM 或 Jev 類模型比較 | 同一資料集比較錯誤率及總成本 |
| 內部文件問答 | 權限過濾後檢索 | 文件版本、適用範圍、引用 |
| 跨文件關係 | 關係索引或 GraphRAG | 是否有足夠關係證據 |
| 未知路徑的多步研究 | Agentic Retrieval | 限制輪數，保留每次查詢理由 |
| 即時外部資訊 | 搜尋、Web、API | 日期、來源、資料缺口 |
| 寫入外部系統 | 授權工具與冪等控制 | 人工核准條件、回執、重複防護 |

部署是另一維度：SaaS、私有部署或混合部署需依資料分類、成本及能力評估；不能直接把某個檢索方法等同某個部署方式。

## 決策程序

1. 先套用不可違反的權限與業務規則。
2. 由 LLM/Agent 判斷是否已有足夠輸入，缺少必要條件則補問或檢索。
3. 選最小足夠路徑，記錄選擇理由、估計成本與驗收方法。
4. 執行後以實際數據驗證，不把模型自評當唯一證據。
5. 若失敗，判斷補充資料或變更方法是否有合理改善空間。
6. 無權限、資料不可得、達預算／期限／重試上限時停止，交付已完成部分與缺口。

Jev 不應成為所有任務的預設前置呼叫。若引入它增加錯誤回補、等待或整合成本，應保留較簡單路徑。
